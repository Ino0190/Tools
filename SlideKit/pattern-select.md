# 型の選び方（34型を2段で絞る）

構成ファイル `<deck>.structure.md` を書くときに、各スライドの型IDをここで決める。
座標と実物は `pattern-catalog.html`（P01〜P18）と `diagram-catalog.html`（D01〜D16）が正本。

型が20を超えると一度に比べきれず選択が雑になる（2026-08-21調査）。
**まず6分類のどれかに決め、その中だけで型を選ぶ。** 一度に比べる候補を10以下に保つ。

## 第1段: 6分類

| 分類 | 何をするスライドか | 候補 |
|---|---|---|
| A 導入・区切り・締め | 始める・章を切る・1行残す・終える | P01 P02 P03 P12 P13 P14 |
| B 文字で語る | 言葉の順序で理解させる | P04 P05 P17 |
| C 数と比較 | 数字を読ませる・案を並べる | P09 P06 P07 P18 D09 D12 |
| D 構造と流れ | 関係・手順・階層を見せる | P08 D01 D02 D03 D04 D07 D08 D10 D13 D14 D15（＋D11 仮置き） |
| E 時間 | いつ何が起きるかを見せる | P10 D05 D06 D16 |
| F 画像 | 写真・画面を見せる | P11 P15 P16 |

合計34型（A6・B3・C6・D12・E4・F3）。D11は中身が決まるまでの仮置きなので、比べる候補には数えない。

判断の順序は「相手が次に何をするか」→分類→型。迷ったら C か D で止まりやすいので、
**数字を引用・照合させるなら C の表（P07/P18）、関係をつかませるなら D** で切り分ける。

## 第2段: 分類の中で選ぶ

### A 導入・区切り・締め

| 条件 | 型 |
|---|---|
| 冒頭 | P01 |
| 章が5つ以上ある | P02（4つ以下なら目次を置かない） |
| 章の切り替え | P03 |
| 1行だけ覚えて帰ってほしい | P12 |
| 締めと次の動き | P13 |
| 謝辞だけ | P14 |

### B 文字で語る

| 条件 | 型 |
|---|---|
| 見出し＋リード＋箇条書き | P04 |
| 同じ重さの要点が3つ並ぶ（3つの柱・3つの特徴） | P05 |
| 箇条書きに入れ子がある | P17 |
| 項目が7つを超える | スライドを割る（型を変えない） |

使わない条件＝**1つの数字が主役なら P09、2案の対比なら P06**。箇条書きで並べない。

### C 数と比較

| 条件 | 型 |
|---|---|
| 指標が1〜3つで、それが主役 | P09 |
| 2つの案・前後を対比する | P06 |
| 3案以上を2軸以上で比べる | P07 |
| 表の行に大項目のまとまりがある | P18 |
| 量の大小そのものを見せる | D09 |
| 提案書で評価軸と対応を示す | D12 |

使わない条件＝**相手が数字を引用・照合するならグラフにしない**（表の方が確かめやすい）。
P09 に指標を4つ以上足したくなったら、それは P07（比較表）か D09（棒グラフ）。

### D 構造と流れ

図解にする前に、下の「図解ゲート」を通す。通らなければ B か C に戻る。

| 条件 | 型 |
|---|---|
| 手順が一直線で4段階前後・文字で足りる | P08 |
| 手順に各段階の成果物も見せる | D13 |
| 分岐（Yes/No）がある | D01 |
| 階層・積み重ね | D02 |
| 繰り返して回る | D03 |
| 初期案→レビュー→検証→改善と進み、改善から初期案へ戻して確定させる | D14 |
| 2軸で位置づける | D04 |
| 中心と周辺の依存 | D07 |
| 課題→本質→方針で整理する | D08 |
| 共通と固有の重なり | D10 |
| 段階的な対策を6段階前後で並べる | D15 |
| 図が要るが中身が未確定 | D11（プレースホルダー・確定前だけ） |

### E 時間

| 条件 | 型 |
|---|---|
| フェーズ帯＋節目 | D05 |
| 日付の帯（工程表） | D06 |
| 単線の年表 | P10 |
| 複数レーン＋節目 | D16 |

### F 画像

| 条件 | 型 |
|---|---|
| 画像が主役で文字は帯1本 | P15 |
| 画像と説明を左右に置く | P11 |
| 画像の周囲に複数の説明を置く | P16 |

## 図解ゲート（D系を選ぶ前に通す2つの問い）

出典＝coleam00/excalidraw-diagram-skill（2026-08-21調査）。

1. **同型性**: 文字を全部消しても、形だけで言いたいことが伝わるか。伝わらないなら図を作り直す
2. **学べるか**: その図から具体的に何か学べるか。**箱にラベルを貼っただけ**になっていないか

両方を通らない図は作らない。文字系（B）か数と比較（C）に戻る。

深さの使い分け＝考え方や方針を説明するなら抽象的な形、実在の仕組み・構成を説明するなら
具体物と実際の数字を入れる。

## 図解にしない条件（まとめ）

- 項目が多い比較 → 表（P07 / P18）
- 条件分岐が多い規則 → 表か箇条書き（語の正確さが要る）
- 語義の定義 → 文字（P04 / P12）
- 単一の指標 → P09。図解ではない
- 引用・発言 → 文字。図解ではない

## 絵・画像が要るときの行き先

SlideKitが自前で描けるのは **箱・線・矢印・円と文字**（`.tb` `.rect` `.flow` `.li` とSVG図形）だけ。
それで足りないものは**別のKitで素材を作って、画像の型（P11 / P15 / P16）に貼る**。

### 線引き: SVG図形で描くか、画像にするか

| 条件 | 作り方 | PPTXでの扱い |
|---|---|---|
| 箱・線・矢印・円で表せる | D系の図解（SVG図形＋`.tb`ラベル） | 図形と文字のまま。**あとから編集できる** |
| 曲線・陰影・質感・実物の形が要る | 別Kitで画像を作り P11/P15/P16 に貼る | 画像になる。**編集できない** |
| 物が動く・流れる様子が主題 | CadKitでコマを焼き mp4 にして `<video>` で貼る | 動画。**再生できる**（プレビュー1枚は選べる） |

迷ったら図形側にする。編集できる形で残す方が、指摘を受けてから直せる。
**画像に文字を焼き込まない。** 画像は絵だけにして、ラベルは透明背景の `.tb` を重ねる
（焼き込むとPPTXで直せなくなる・MUST規則）。

### 何で作るか（2026-08-21 実装を確認して修正）

**スライド1枚がそのまま入る（自動）** ＝ボタンを押すとデッキに挿入される。

| 要るもの | 経路 | PPTXでの扱い |
|---|---|---|
| 表（実データ・計算式つき） | SlideKitの「＋表(CalcKit)」→CalcKitで範囲選択→「スライドへ追加」 | ネイティブの表。**編集できる** |
| 工程表・ロードマップ | SlideKitの「＋ガント」→GanttKitで調整→「このガントをスライドへ追加」 | 図形と文字。編集できる |
| 実データのグラフ | 同じ「＋表(CalcKit)」からグラフを選ぶ（DashboardKit必須） | **PNG**。タイトルと凡例だけ編集できる |
| 数値のグラフ（手で書く） | `data-chart` に数値をJSONで書く（SPEC.md 5.7） | **ネイティブグラフ**。数値も文字も編集できる |

**人が運ぶ（自動化されていない）** ＝ファイル保存かクリップボード経由。SlideKit側はKit名を知らない。

| 要るもの | 使うKit | 運び方 | 入るときの形 |
|---|---|---|---|
| アイコン・記号・ロゴ | BezierKit | 「スライド用コピー」→**HTMLソースに貼る**（Kiro経由） | インラインSVG＝図形のまま編集できる |
| 立体物・機械・建物・3Dの俯瞰 | CadKit | 撮影PNG／線画SVGを保存→SlideKitにドロップ | PNGは画像。**SVGはインラインSVGで入り、PPTXで図形になる**（2026-10-14〜） |
| 写真の現像・合成・不要物消去 | PictureKit | 書き出したPNG/TIFFをドロップ | 画像 |
| 画面のスクリーンショット | CaptureKit | クリップボードへコピー→⌘V | 画像 |
| AWS・システム構成図 | ArchKit | **画像書き出しが無い**。CaptureKitで撮る | 画像 |
| 手描き風の絵・自由なイラスト | **持っていない** | 外部で作って貼る（最後の手段） | 画像 |
| 荷が流れる・機械が動く動画 | CadKit → SlideKit | `cdp-run.py --export-flow` → `flow_to_movie.py` → `<video>` | **動画**（PPTXでも再生できる） |
| 相手に回してもらう3D | CadKit | `bhs-export.py --frames 24` でアニメ入りGLB → PowerPointで手挿入 | **3Dモデル**（自動変換に乗らない） |

**動く図が要るとき**（荷の流れ・搬送・工程の進み方が主題のとき）:

```
python3 CadKit/cdp-run.py bhs --export-flow /tmp/flow --flow-frames 16 --flow-step 1.1 \
    --line-angle 18,30 --line-outer 2.0 --line-inner 0.6 --line-size 1800,760 --export-on-fail
python3 SlideKit/flow_to_movie.py /tmp/flow -o <deckのフォルダ>/xxx.mp4 --fps 8 --scale 2
```

🚫 **SVGのアニメでは渡せない。** ブラウザでは動くが、PPTX変換でPNG1枚になる。
動かすなら動画一択（詳細は `SPEC.md` 4.3）。再生前に見えるプレビューは
`xxx_frames/index.html` を開いて動画を見ながら選ぶ。

CadKitの線画SVGとBezierKitの絵は、ドロップでも貼り付けでもインラインSVGで入り、PPTXでPowerPointの図形になる
（2026-10-14〜。前に作ったデッキに残っている `<img>` のSVGも、変換のときに図形にする）。線の太さや色はPowerPointで直せる。

手描き風のイラストと、矢印が複雑に絡むスキーム図はこの仕組みの苦手な領域。
座標が崩れて要素が重なるので、D系で無理に描かない。**図を分ける**か、
別Kitの画像にするか、そのスライド自体をやめる。

### 画像枠の実寸（素材を頼む前にこの比率を出す）

| 型 | 枠 | 比 | 注意 |
|---|---|---|---|
| P11 画像+テキスト（右画像） | 560×400px | 1.40:1 横長 | 左に説明文560×400 |
| P15 全面画像+半透明帯 | 1280×720px | 1.78:1 横長 | `object-fit:cover` でトリミングされる。中心に主題を置く |
| P16 画像+周囲説明 | 600×380px | 1.58:1 横長 | 上下左右に説明250×120が4つ入る |

🔴 **どの枠も横長。縦長の写真や正方形の図は入らない。**
縦長の素材しか無いなら、型を変える（P04の本文＋小さい画像にする）か、
横に2枚並べる構成に変える。枠に合わない素材を頼まない。

### 素材の書き方＝「誰が何をしている絵か」まで書く

`- 素材:` は道具名だけ書いても伝わらない。**被写体・動作・場面**を書く。
枠の比率も添える（上の表から引く）。

| ✕ 道具だけ | ○ 何の絵か |
|---|---|
| CaptureKitでスクショ | コーチがタブレットで選手の睡眠グラフを見ている画面（S1統合版・560×400で切る） |
| CadKitでレンダリング | 検査機から便別シュートまでを斜め上から見た俯瞰（1280×720・中央にソータ） |
| PictureKitで写真 | 選手が計測機器を装着している場面の写真（横位置・顔は写さない） |
| BezierKitでアイコン | 睡眠・心拍・練習量の3アイコン（単色・#21537f） |

表とグラフと工程表は**素材を頼まなくていい**。SlideKitの「＋表(CalcKit)」「＋ガント」で
デッキに直接入るので、構成ファイルには型IDだけ書けばよい（素材行は不要）。

```markdown
## 4. 荷物の流れ [P15]
- 主張: 検査から便別の積み込みまでが1本の流れになっている
- 根拠: 成田・ダイフクの公開記事
- 素材: 検査機→ソータ→便別シュート→ULDを斜め上から見た俯瞰。CadKitの#bhsシーン（1280×720・横長）
```

手元に素材が無い場合も、**何の絵が欲しいかを先に書く。** 「ここに〇〇している画像を入れたい」が
構成に残っていれば、撮る・作る・探すの判断ができる。空欄のまま進めると、
HTMLを書く段階で枠だけ残って中身が入らない。
