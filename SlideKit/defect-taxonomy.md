# スライドの欠陥分類表

生成したスライドを点検するときは、自由に眺めるのではなく**この表と照合する**。

根拠＝[SlideAudit（UIST 2025・arXiv 2508.03630）](https://arxiv.org/abs/2508.03630)。
専門家の分類体系で2,400枚を注釈し、LLMに欠陥を探させた研究。**AIの自由な批評は F1 0.331〜0.655 で当たらない。
分類体系を渡したプロンプトが最高性能**で、改善試験でも分類体系併用の方が改善幅が大きかった（82.0%のうち87.8%）。
＝「おかしいところを探して」ではなく「この表のどれに当たるか」を見る。

分類はこのワークスペースで実際に起きた欠陥から作っている（2026-08-21）。
検出方法の欄が **機械** のものは人が見なくてよい。**目** と **LLM** が人とAIの仕事。

## 直し方の優先順位（どの欠陥でも共通）

1. レイアウトを変える（型を替える・要素を減らす）
2. 画像や図を小さくする
3. 文字と余白を詰める
4. **最後の手段としてスライドを割る**

上から試す。いきなり分割すると話の単位が壊れる。

## B 壊れる（PPTXで内容が消える・別物になる）

| ID | 症状 | 検出 | 直し方 |
|---|---|---|---|
| B1 | 許可外のclassを使い、PPTXで内容が消える | 機械 `slide-guard②` | `.tb .rect .flow .li` に置き換える |
| B2 | カタログ外の色でPPTX変換が止まる | 機械 `slide-guard③` | トークンの色にする。意図的なら `<html data-palette="custom">` |
| B3 | 文字をSVGや画像に焼き込み、PPTXで編集できない | 目（SVG内の`<text>`を探す） | 図形だけ残し、ラベルは透明背景の `.tb` を重ねる |
| B4 | 角丸がPowerPoint既定（短辺16.7%）になり巨大化する | 機械 `tests/test_radius.py` | `adj = radius / min(w,h)` の正規化を壊していないか見る |
| B5 | data属性とinline styleがずれ、画面とPPTXで位置が違う | 機械 `run_check⑥` | 両方を同値に直す。片方だけ変えない |
| B6 | SVGをスライド直下にむき出しで置き、PPTXで絵ごと消える | 機械 `slide-guard⑫`（fail） | `data-x/y/w/h` の div で包む（PPTXでは図形のグループになる） |

## F 収まらない（はみ出し・重なり）

| ID | 症状 | 検出 | 直し方 |
|---|---|---|---|
| F1 | 要素が1280×720の外に出ている | 機械 `slide-guard⑤` | 座標を内側へ。型の座標値に戻すのが早い |
| F2 | `.rect` 同士が重なっている | 機械 `run_check①` | 要素を減らすか、型を2枚に分ける |
| F3 | 箱の中で文字があふれている | 機械 `run_check②`・`.flow` は `measure` | 文字を削る→箱を広げる→font-sizeを下げる（下限15px） |
| F6 | ブラウザに見えるのにPPTXに出ない文字（`.tb` に入れていない自由配置） | 機械 `slidecheck の measure` | `.tb` に入れる。変換を `--measured` にすれば見えている通りに拾う |
| F7 | 依頼の枠（イラスト・グラフ・写真）が残ったまま | 機械 `slide-guard⑪` | 「📋 依頼文をコピー」で用意して枠に貼る。グラフは data-chart に置き換える |
| F4 | 画像のアス比が枠と違って歪む | 機械 `run_check④` | 枠を画像の実寸比に合わせる（P11=560×400／P15=1280×720／P16=600×380） |
| F5 | 表が自動高さで下へ伸び、他の要素に被る | **目**（診断で出ない） | `slidecheck.py --shot` で必ず目視。行を減らすか2枚に割る |

## R 読めない

| ID | 症状 | 検出 | 直し方 |
|---|---|---|---|
| R1 | フォントが下限を割る（主文19px未満・カードの中の文17px未満・注記/グラフは15px・表は8pt=10.67px・図解のみ13px可）／表の外の文字の6割超が19px未満 | 機械 `slide-guard①` | 文字を削って大きくする。小さくして詰め込まない |
| R2 | 1枚の文字が多い（`.tb`で900字超。実測 p50=279／p95=656） | 機械 `slide-guard⑧` | 図解にする→2枚に割る |
| R3 | 地色と文字色のコントラストが足りない（WCAG: 通常4.5:1・大きい文字3:1未満） | 機械 `slidecheck の measure`（文字の真下に見えている地の色と比べる） | トークンの組み合わせに戻す（暗地なら `#fafafa`／明地なら `#121212`） |
| R4 | 1行が長すぎて目が戻れない | **未実装**（目で見る） | 箱幅を狭める。2カラムにする |

## M 伝わらない（ここがAIの弱点。表と照合する）

| ID | 症状 | 検出 | 直し方 |
|---|---|---|---|
| M1 | 誰に渡す資料か決まっていない | 機械 `slide-guard⑥`（fail） | 構成ファイルの「誰に」を埋める。埋まらないなら作らない |
| M2 | 理解してほしいことが決まっていない | 機械 `slide-guard⑥`（fail） | 同上。相手が説明できるようになる状態を1文で書く |
| M3 | 主張が無い、または2文以上ある | 機械 `slide-guard⑥`（warn） | 1スライド1メッセージ。2文になったらスライドを割る |
| M4 | 主張だけを上から読むと話が通らない | **LLM**（`structure-preview.py` のリスト、HTMLの実際の見出しは `slidecheck の deck-lint` のタイトル一覧を読む） | 順序を替える。抜けている主張を足す |
| M5 | 図解が0枚で文字だけ並んでいる | 機械 `slide-guard⑦` | `pattern-select.md` のD系に置き換わる枚を探す |
| M6 | 図解が「箱にラベルを貼っただけ」になっている | **LLM**（図解ゲート2問） | 文字を消しても形で伝わるか／何か学べるかを問う。通らなければ文字か表に戻す |
| M7 | 型の選択が内容に合っていない（数字を照合させたいのにグラフ等） | **LLM**（`pattern-select.md` の6分類） | 相手が次に何をするかで選び直す |
| M8 | 根拠が「〜と思われる」で数字も出典も無い | **LLM** | 数字か出典を入れる。無ければその主張を落とす |
| M9 | 全部の枚が同じ濃さで、どこが要か分からない（キースライド未定・山が2つ以上） | 機械 `slide-guard⑥`（warn） | 構成ファイルにキースライドを1枚決め、その前後だけ「濃い」、他は「薄め」にして文字を減らす |
| M10 | 同じものを枚ごとに違う言い方で書く（表記ゆれ） | 機械 `deck-lint`（warn・案件の `terms.md` を上へたどって読む） | 用語表の「使う」にそろえる。初出だけ「使う（使わない）」と言い添えてよい |
| M11 | 同じ指標が枚ごとに違う値になっている | 機械 `deck-lint`（warn） | 元の数字に戻す。別の時点・範囲なら、その違いを文に書く |
| M12 | タイトルの「3段階」と本文の連番（STEP 4まで）が食い違う | 機械 `deck-lint`（fail） | 数を実態に合わせるか、まとめ方を変える |
| M13 | タイトルが「この」「その」で始まり、1枚で読めない | 機械 `deck-lint`（warn） | 指しているものを名指す |
| M14 | 主張に効いていない部品がある／補足が注記なのか結論なのか見た目で分からない（グラフの下の文・右の補足欄・下の帯など） | **LLM**（一覧画像を文字を読まずに見る。最初に目に入るものがその枚の主張と同じか、次に読む場所が分かるか） | 主張に効かない部品は消す。注記は説明する対象のすぐ近くに小さく置く。結論ならタイトル（主張）へ上げる |
| M15 | 骨格が欠けている（アジェンダ・振り返りと論点・説明・報告・次回に向けた確認のどれかが無い）／同じ論点の枚が何枚も続く／同じ相談が2か所にある | **LLM**（構成ファイルの「役割」を上から読む。`structure-preview.py` が役割ごとの枚と、3枚以上ある論点を出す） | 欠けた役割を足す（欠けてよいときは「- 骨格: 〇〇は無し（理由）」）。同じ論点の枚は1枚にまとめられないか試す。相談は論点の枚か次回に向けた確認に集める |

M14は、LayerXの記事「『見た目はいいけど、伝わらない』AIスライドを改善する試行錯誤」の実験で挙がった問題から足した（2026-10-31）。記事では、全文を読まなくても要点と読む順序が分かるかを画像で点検している。
M15は、2026-10-31 利用者「この項目がカバーできているかを検討するのが良さそう」から足した。最初の版から枚数が増えたデッキが28本中14本あり、足された枚の多くは、同じ書式で項目ごとに割った枚と、見せる枚の次に置いた相談の枚だった。

## A 相手に関係ない（利用者が繰り返し指摘してきた型）

| ID | 症状 | 検出 | 直し方 |
|---|---|---|---|
| A1 | こちらの工程・体制・開発日程が主役になっている | **LLM** | 相手の判断に関わらない限り落とす |
| A2 | 相手が知っていることを相手に説明している | **LLM** | 削る。読み手はその相手であって第三者ではない |
| A3 | 聞く資料なのに説明資料になっている（答えの範囲を先に狭める） | **LLM** | `asking-voice-detail.md` の6つの仕上げチェックを回す |
| A4 | 情報は正しいが相手が次に何をするか分からない | **LLM** | 構成ファイルの「相談したいこと」をスライドに落とす |
| A5 | 「〜だけ」で話す範囲を狭める／次のページの予告をする | 機械 `slide-guard⑩` | 「だけ」を外す（限るなら理由が伝わる語）。予告の文は消して、そのページで話す |
| A6 | 未決を「要確認」「TBD」「調整中」だけで置く | 機械 `slide-guard⑩`（同じ枚に「仮」「までに」等が無い時） | 仮＝○○で進めている／いつ誰から確定をもらう／無かったときの扱い、の3点で書く |
| A7 | 「世界初」「公開事例は無い」など、無いことを書く | 機械 `slide-guard⑩` | 見つかった事実を肯定形で（対象・規模・出典）。無いことは確かめられない |
| A8 | 決めつけ（「これが〜の本質です」「〜こそ」）・盛り語・前置き | 機械 `slide-guard⑩`（言い回し）＋**LLM**（文の組み立て） | 事実を書いて止める。自分の考えなら「〜と思っています」（`.kiro/steering/inouchi-voice.md`） |
| A9 | 「〜しておこう」「〜しておきましょう」 | 機械 `slide-guard⑩` | 「〜する」「〜してください」 |
| A10 | 対比（「AではなくB」「AよりBが大事」）が2回以上 | 機械 `slide-guard⑩` | 言い切る形に直す。対立そのものが中身のときだけ1回残す |
| A11 | 外に出さない名前・内部の呼び名が残っている（他の顧客名・試作の版名など） | 機械 `deck-lint`（fail・`forbidden-terms.txt` を上へたどって読む＋`~/.config/slidekit-forbidden.txt`） | 消すか、相手に通じる言い方にする。リストは SlideKit の外（案件フォルダか ~/.config）に置く |

LLMの項目は `python3 SlideKit/slidecheck.py <deck>.html --review` で点検用のプロンプトにまとめられる
（構成ファイルの「誰に」・全枚の文字・この表のM/A・一覧画像。外部には送らない）。

## この表の使い方

・**生成した直後**に B〜A を上から照合する。機械の項目は `python3 SlideKit/slidecheck.py <deck>.html` で出る
・機械が緑でも M と A は残る。ここは表を見ながら自分で点検する（自由に眺めても当たらない）
・表に無い違和感を見つけたら、**項目を足してから**直す。次から照合できる
・未実装（R3 R4）は測る手段がまだない。視覚QAループを作るときに機械側へ移す

## レビューの指摘の受け方（採否表）

作った本人には見えない破綻を拾うため、`--review` のファイルを**新しいチャットに貼って**読ませる（作った経緯を知らない目で読ませる）。
読ませる立場は `--as "PwCのパートナー"` のように変えられる。利用者がチャットで「〇〇だったらどう思うか」と聞いたときも、同じ形で返す。

返ってきた指摘は全部直さず、1件ずつ表にする（jinba-consulting-pptx-skill の content-review-prompt.md を参考・2026-10-18）。

| # | 枚 | 指摘（原文のまま） | 種別 | 採否 | 対応／理由 |
|---|---|---|---|---|---|
| 1 | 3枚目 | 「十分」の根拠がその枚に無い | 論理 | 採用 | 測った値と期間を足した |
| 2 | 5枚目 | 「アスログ」が分からない | 日本語 | 不採用 | 相手の呼び方。読み手には通じる |

・種別＝日本語／論理／破綻（数・図・数値）／体裁。採否＝採用／不採用／保留
・直さない指摘は、理由を1行書く（表現の好み／読み手には通じる／事実として正しい）
・意味が変わる言い換えや、構成の組み替えは「保留」にして、利用者に決めてもらう
・採用した分を直したら slidecheck を回し直す
・この表に無い種類の指摘が来たら、表に項目を足す（次から照合できる）
