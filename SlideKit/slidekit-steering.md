# SlideKit スライド生成規則（判断ガイド・2026-08-05減量）

**MUST規則とカラートークンの正本は `.kiro/steering/slide-contract.md`（常時読込）。**
ここは「どの型・どの表現を選ぶか」の判断ガイドだけを持つ。

- 型は `pattern-catalog.html`（P01〜）と `diagram-catalog.html`（D01〜）を**開いて選ぶ**。
  座標計算済み・文言差し替えだけで使える。一覧表はここに再掲しない
- 手順書（画像・SVG・プレースホルダーの書式）は `SPEC.md` 14章
- 変換仕様・data属性の全定義は `SPEC.md` 5章

## スライド設計の判断

**本文を置く前に、このスライドで理解させることを1文で定義する。**
元原稿の箇条書きをそのままカードへ転記しない。

| 情報構造 | 優先する表現 |
|---|---|
| 3項目以上を同じ観点で比較 | 比較表 |
| 項目と2つ以上の属性が対応 | 対応表・マトリクス |
| 手順・因果・開始点から到達点 | フロー図 |
| 部門をまたぐ工程 | スイムレーン（[CUSTOM]で組む） |
| 時間・段階・将来計画 | タイムライン・ロードマップ |
| 循環・反復 | 円環図 |
| 階層・分類 | ツリー図（[CUSTOM]で組む） |
| 要素間の依存・相互作用 | 依存関係図 |
| 防御・審査・関門 | レイヤー図・ゲート型フロー |
| 全体と構成要素 | 中心＋周辺要素 |
| 2軸による整理 | 2軸マップ |
| 数値の推移・構成比 | `data-chart` のグラフ（単位の混在禁止＝契約の規則3） |
| UI・操作・実物 | スクリーンショット |
| 上記に該当しない主張 | 文章・箇条書き |

- 表のセルは1セル1論点。行数が多い場合は文字を縮小せず分割する
- 図解内の要素名は原則20文字以内、補足は2行以内
- 図を見れば分かることを箇条書きで再説明しない
- 箇条書きの方式（詳細は SPEC.md 5.2.1）: 階層がある／PowerPointで書き足す資料は
  `data-bullet="native-disc"`＋`<div class="li" data-lvl="0">`（マーカー文字は本文に書かない）。
  カード列・1行だけの補足は `data-bullet="disc"` で1枠1項目
- 文章またはカードだけのスライドを3枚以上連続させない
- 図解方式が複数ある場合は最大3案を検討し、最も単純に読める案で初稿を作る
- 図解の理由を説明できない場合は、無理に図を入れない
- 生成後はHTMLをレンダリングし、PPTX変換後も重なり・文字切れ・視線誘導を確認する

## 文章ルール（1枚単独で通じる文・2026-08-06利用者指摘）

生成側は資料全体の文脈を持ったまま文を書くため、「自分しか分からない文」を作りがち。

- **各文は、そのスライド1枚だけを読んで意味が取れること。** 他のスライドや表の構造を
  前提にした指示語・省略（「前の問い」「この3つ」「上記の〜」の別スライド持ち出し）は使わない
- レトリック（「〜こそ〜」の対句・倒置・体言止めの連続）でメッセージ然とした文を作らない。
  主語＋動詞で普通に言い切る
- 抽象的な主張には具体例を1つ添える（例: 「課題が無いのに作り始める」）
- **誰と誰の関係で読まれるかを確認する。** 顧客との共同作業の資料で、作り手側（AWS等）を
  「正解を持つ側」に置く表現をしない（「叩き台と突き合わせる」「答え合わせ」等は
  相手の答えを査定するように読める）。進行者目線の段取り語もスライドに漏らさない
- **出典は文字列で書かず、必ず `<a href>` リンクにする**（2026-08-07利用者指示・PPTX変換でも
  ハイパーリンクとして残る）。URLは推測で書かず、検索または実在確認（HTTP 200）したものだけ使う
- NG実例（2026-08-06〜07に差し戻したもの）:
  「人によって答えが違う場所こそ、チームの前提がずれている場所」
  「前の問いがNoのまま進むと、あとの投資が全部無駄になる」
  「書いたら共有 → そのあとAWSの叩き台と突き合わせる」（顧客向けで上から目線）

## フォントサイズ（PPTX pt換算で判断）

下限は契約の規則8（スライドの主文22px以上・カードの中18px以上・注記/表/グラフは15pxまで可・図解D系スライドのラベルのみ13px可）。加えて（2026-11-18 投影で小さいとの指摘を受け既定を底上げ）:

- 見出し40px（カタログ既定）／リード・本文・補足26px／キャプション・出典18px以上。迷ったら26px
- 表紙タイトル54px／サブタイトル28px
- プロジェクター投影（授業・会場）は本文26px以上、注釈20px以上
- 作成後の点検: `grep -o 'data-font-size="[0-9]*"' 対象.html | sort -u` で主文22px未満・カード18px未満・注記15px未満が無いこと

## 余白とカード（脱AIの実装数値・数値はここが正本）

原則（2026-11-01 `.kiro/steering/datsu-ai-rules.md` から移した。ここが正本）＝中身に合わせて形を決める。
テンプレートに中身を流し込まない。とりあえずカードを並べず、比較は表・工程はフロー・時間はタイムラインにする
（上のパターン選択ガイド）。見出しに飾りの絵文字（🎯💡🚀✨）を入れない。グラデーションは表紙・扉・メッセージの枚に限る。

- **カードを中身より縦長にしない**（最重要・AI臭の元）。中身が見出し＋2〜3行ならカードもその高さ。
  余ったスペースはカードを伸ばして埋めず、塊の上下の余白として残す
- 情報の塊と塊の間は**40〜60px**（2行分）。同じ塊の中の要素間は8〜14px
- **表題と中身は離さない**（近接の原則）: 見出し→直下の内容は8〜12px。内容ボックスは
  `justify-content:flex-start` にする（`.rect` 既定の縦中央寄せで中身が見出しから離れる事故が定番）
- まとめ・締めの文は枠（rect）で囲まず、テキスト直置き
- 濃い色の `border-top` / `border-left` は使わない。カードの区別は背景色＋見出し色で足りる。
  表の薄い罫線（#d4dde7等）は可。表の大項目はrowspanでなく疑似結合（pattern-catalog P18）
- 同じレイアウトを3枚以上連続させない。項目一覧・対応表はカードでなく表か箇条書き

## 図解と画像の判断

- **構造・流れ・位置づけのスライドは、箇条書きや表でなく図解を第一候補にする。**
  型は `diagram-catalog.html` を開いて選ぶ
- **数値のグラフ（縦棒・横棒・積み上げ・折れ線・円）は `data-chart`**（SPEC.md 5.7）。PPTXでネイティブグラフになり
  PowerPointの「データを編集」で直せる。D09（図形の棒）は数値を照合させない量の比較に限る
- 曲線・3D風・ファネルはネイティブ図形で作らず**SVG方式**（手順はSPEC.md 14.2。
  SVGは図形専用・文字は透明 `.tb` を重ねる＝契約の規則5）
- **体制図（箱＋接続線の階層）・スイムレーン・大きな構成図は `[CUSTOM: 理由]` で組んでよい**（契約の規則1）。
  `.rect`/`.tb`/`.flow` で組み、`slidecheck.py` の実測を0件にしてスクショで確かめる。
  中身が決まっていない時だけ D11（図解プレースホルダー・SPEC.md 14.3）か過去PPTXの図の移植
- UI・画面・操作手順の説明は文字だけにせず**スクショ用プレースホルダー**を置く
  （書式はSPEC.md 14.4）。概念・構成・数値の説明には不要
- **線画のイラスト（人のピクトグラム・物・場面の説明図）は Kiro が SVG で描いてよい**。色はトークンの1〜2色、
  線の太さを揃え、文字は入れない（ラベルは `.tb`）。PPTXでは図形のグループになり、BezierKitで直せる（SPEC.md 8.6.1・8.6.2）。
  写真のような絵・表情・込み入った場面は描かず、依頼の枠にする
- **イラストや写真、グラフがあると伝わりやすいと考えた場所には、依頼の枠を置く**（`data-ask`・SPEC.md 14.5）。
  文字で埋めたり、それらしい図形で代用したりしない。枠の中に「伝えたいこと」と、
  イラストなら描くもの・構図・画風・入れないもの、グラフなら作り方（data-chart の項目と値）と探し方（検索語）を書く。
  画像に文字は入れてもらわない（文字はスライド側の `.tb` で書く＝契約の規則5）
  手元に数値があるグラフは枠にせず、最初から data-chart で作る
- 画像はコンテナをアス比に合わせる・WebP/HEICはJPG化（詳細はSPEC.md 14.1）

## 生成後セルフチェック

- [ ] 各スライドにパターンID宣言があるか（`<!-- SLIDE: 名前 [P09] -->`・無ければCUSTOM理由）
- [ ] 全要素のdata属性とstyleが一致しているか
- [ ] カタログにないhex・座標を使っていないか
- [ ] テキストが枠に収まる長さか（見出し25字・カード本文4行・箇条書き1行40字目安）
- [ ] 各文がスライド1枚単独で意味が取れるか（文脈依存の指示語・レトリック頼みの文が無いか）
- [ ] 出典がすべて `<a href>` リンクになっているか（文字列だけの出典が無いか）
- [ ] `data-font-size` に下限割れが無いか（主文22px以上・カードの中18px以上・注記/表/グラフ15px以上）
- [ ] カードが中身より縦長になっていないか・塊間に40px以上の余白があるか
- [ ] UI・画面・操作の説明スライドにスクショ用プレースホルダーを置いたか
- 仕上げに `python3 SlideKit/slide-guard.py 対象.html` を実行（変換時にも自動実行される）
